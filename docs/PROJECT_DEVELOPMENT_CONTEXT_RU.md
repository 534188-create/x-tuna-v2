# Контекст разработки проекта x-tuna v2

> Живой инженерный справочник для продолжения разработки без повторного
> исследования репозитория. Документ не является журналом чата, дампом логов
> или хранилищем производственных секретов.

## Паспорт проекта

| Поле | Значение |
|---|---|
| Название | `x-tuna` |
| Назначение | Транзакционный постконфигуратор уже установленной панели LucX |
| Поддерживаемые ОС | Debian 12 и Debian 13 |
| Минимальная версия Python | 3.11 |
| Основная команда | `x-tuna` |
| Совместимая команда | `lucx-post-configure` |
| Лицензия | `AGPL-3.0-only` |
| Основной артефакт | `dist/lucx-post-configure.sh` |
| Сборка | `python3 tools/build_installer.py` |
| Тесты | `PYTHONPATH=src:tests python3 -m unittest discover -s tests` |

Проект запускается после ручной установки LucX, создания необходимых inbound,
клиентов и сертификатов. Он настраивает только согласованную внешнюю обвязку:
маршрутизацию, защиту, подписки, проверку сертификатов, резервирование,
восстановление и эксплуатационный TUI.

## Цели и границы

### Что делает проект

- выполняет read-only аудит установленного LucX;
- обнаруживает inbound, транспорт, SNI, Host endpoints и listeners;
- формирует обезличенный manifest и человекочитаемый план;
- получает цифровое подтверждение перед изменениями;
- создаёт консистентную резервную копию;
- генерирует конфигурации во временном staging-каталоге;
- проверяет конфигурации реальными бинарниками;
- применяет изменения атомарно;
- проверяет живые службы и маршруты;
- автоматически выполняет rollback при критической ошибке;
- предоставляет цифровой TUI через `x-tuna`;
- восстанавливает внешнюю обвязку после обновления LucX;
- собирает автономный installer без `pip` на целевом сервере.

### Что проект не делает

- не устанавливает LucX;
- не создаёт администратора панели;
- не создаёт inbound и клиентов в обычном режиме;
- не переносит production-клиентов, UUID, subId, пароли или ключи;
- не выпускает сертификаты без отдельного подтверждаемого действия;
- не редактирует исходный Naive Caddyfile;
- не изменяет внутренние listener-порты без отдельного режима;
- не публикует qWDTT в подписках;
- не выдаёт TrustTunnel QUIC, если выбран HTTPS-вариант;
- не считает один запущенный процесс доказательством работоспособности.

## Неподвижные инварианты

Нарушение любого правила блокирует применение или переводит компонент в
безопасный режим без изменения существующей конфигурации.

1. Исходный Naive Caddyfile только читается.
2. Для найденного Caddyfile контролируются содержимое, тип, владелец и режим.
3. Клиенты, UUID, subId, credentials и ключи не изменяются автоматически.
4. Внутренний порт не меняется при изменении публичного endpoint.
5. Reality SNI читаются из актуального LucX и не угадываются.
6. qWDTT исключается из всех преобразуемых подписок.
7. TrustTunnel QUIC не публикуется клиентам, если выбран HTTPS/h2.
8. Каждая запись имеет backup, проверку и rollback.
9. Manifest перечитывается перед commit; устаревший снимок блокируется.
10. Неизвестная новая схема LucX не изменяется автоматически.
11. Секреты не попадают в argv, журналы, отчёты, fixtures и Git.
12. VPN-маршрут имеет приоритет над заглушкой.
13. Неоднозначный протокол не направляется в backend эвристикой.
14. Перезагрузка сервера не выполняется автоматически без отдельного действия.

## Карта репозитория

### Ядро `src/lucx_post_configurator/`

| Файл | Назначение | Ключевые ограничения |
|---|---|---|
| `models.py` | Модели audit, manifest и настроек | Не хранить секреты в redacted-моделях |
| `discovery.py` | Обнаружение LucX, служб, портов, SNI и Caddyfile | Только чтение |
| `migrations.py` | Миграция версий manifest | Новую неизвестную схему блокировать |
| `questionnaire.py` | Интерактивный цифровой сбор параметров | Подтверждения только числами |
| `planner.py` | Человекочитаемый план изменений | Перечисляет write-set и службы |
| `engine.py` | Оркестрация audit, apply, validate и rollback | Commit только после staging gate |
| `transaction.py` | Backup, atomic commit и восстановление | Не восстанавливать чужие файлы |
| `targetfs.py` | Безопасная работа с целевой файловой системой | Защита symlink и path traversal |
| `validation.py` | Статическая и живая проверка | Process active недостаточно |
| `renderers.py` | Генерация Nginx, HAProxy, nftables, units и logrotate | Только управляемые цели |
| `certificates.py` | Поиск и криптографическая проверка сертификатов | Не выпускать сертификат автоматически |
| `certificate_manager.py` | Управление сертификатами через TUI | Отдельное подтверждение применения |
| `cloudflare.py` | Загрузка актуальных сетей Cloudflare | Не использовать встроенный устаревший список |
| `decoy_capabilities.py` | Классификация безопасной доставки заглушек | Коллизии SNI блокируются |
| `extended_decoys.py` | Матрица расширенной маршрутизации | Не перехватывать неоднозначный VPN |
| `decoy_health.py` | Проверка ожидаемого HTTP-маркера заглушки | Отличать 404 от чужого backend |
| `naive_frontend.py` | Независимый управляемый Naive frontend | Исходный Caddyfile не менять |
| `trusttunnel_backend.py` | Отдельный backend TrustTunnel | Проверять CONNECT и GET отдельно |
| `assets/lucx_sub_sidecar.py` | Встроенный subscription-sidecar | Loopback-only, fail-open, без ID в логах |
| `integrity.py` | Хеш-контроль защищённых объектов | Drift блокирует repair/apply |
| `diagnostics.py` | Редакция секретов и диагностических значений | Секреты заменяются отпечатками |
| `tui.py` | Главное цифровое меню | Не печатать сырые JSON-словари |
| `progress.py` | Progress bar и heartbeat | Не выдумывать процент неизвестной операции |
| `status.py` | Читаемая проекция состояния | Не раскрывать внутренние значения |
| `updates.py` | Источники обновления и detached worker | Worker независим от `x-ui` и SSH |
| `repair.py` | Проверка и восстановление после обновления | Marker удалять только после health-check |
| `self_install.py` | Установка постоянных команд и units | Команды `x-tuna` и совместимые aliases |
| `cli.py` | CLI dispatch и коды завершения | Машинный JSON только для CLI |

### Тесты и инструменты

`tests/` содержит unit-, regression- и integration-тесты для каждой подсистемы.
`tools/` содержит builder, secret scan, documentation checker, live probes,
сравнение SQLite snapshots и staging-проверки. Live tools не должны содержать
реальные IP, домены, subscription IDs или credentials по умолчанию.

## Жизненный цикл применения

```text
preflight
  -> read-only audit
  -> manifest migration
  -> questionnaire
  -> plan and numeric confirmation
  -> backup
  -> staged rendering
  -> binary validation
  -> fresh audit and integrity check
  -> atomic commit
  -> service activation
  -> health-check
  -> complete or rollback
```

До commit допустимы только чтение и staging. При ошибке внешние ingress-службы
возвращаются раньше внутренних backend-служб, чтобы не оставить маршрутизатор,
ссылающийся на отсутствующий процесс.

## Manifest и источники данных

Manifest версии 3 содержит группы `lucx`, `protocols`, `network`, `firewall`,
`cloudflare`, `certificates`, `decoys`, `sidecar`, `updates`, `integrity` и
`settings_management`.

Для каждого inbound сохраняются только необходимые метаданные:

- protocol и remark;
- internal port/listen и TCP/UDP режим;
- transport и security;
- public Host endpoint;
- Reality server names;
- дополнительные port bindings;
- классификация внешней публикации;
- безопасные отпечатки чувствительных matcher-значений.

Секретные поля settings, клиентов и ключей не должны попадать в redacted audit.
Версии manifest мигрируются только однозначно. Версия выше поддержанной требует
остановки, отчёта и выбора пользователя.

## Сеть и публикация

- Панель и подписка могут использовать внешний TCP/443 через Cloudflare.
- Внутренние порты LucX не подменяются внешними портами в базе без точечного
  разрешённого sync-плана.
- TLS inbound могут идти через общий SNI-маршрутизатор только при доказанной
  безопасной стратегии конкретного transport.
- UDP-протоколы сохраняют собственные UDP-порты.
- TrustTunnel при рабочем маршруте через 443 блокируется на обнаруженном
  внутреннем порту извне по TCP и UDP; loopback backend остаётся доступным.
- Mieru и qWDTT нельзя объединять с обычным TLS-маршрутом без подтверждённой
  схемы LucX; их исходные listeners должны сохраняться.
- Неизвестный SNI по умолчанию отклоняется, если fallback не доказан.

Сайты-заглушки классифицируются как `direct`, `existing_fallback`,
`naive_readonly`, `blocked_collision` или `unknown`. Создание каталога не
означает, что сайт разрешено публиковать наружу.

## Подписки

Sidecar необязателен и включается только отдельным цифровым подтверждением.
Он читает SQLite в режиме `mode=ro`, проксирует loopback upstream и возвращает
исходную подписку при ошибке преобразования.

Правила преобразования:

- qWDTT/wdtt не выдаётся ни одному клиенту;
- TrustTunnel QUIC/HTTP3 удаляется, HTTPS/HTTP2 сохраняется;
- TrustTunnel TLV преобразуется в Throne URI только при валидном payload;
- AWG CIDR не должен становиться `%2F32/32` или `/32/32`;
- Mieru `traffic-pattern` для Throne получает исходный Base64 `/`, а не `%2F`;
- диапазон Mieru берётся из `portBindings`, если он есть;
- AnyTLS authority получает публичный Host port, например `443`, а внутренний
  listener остаётся прежним;
- имена подключений, credentials, query и fragment сохраняются;
- Clash/Mihomo получают валидный YAML, а AnyTLS добавляется только при наличии
  безопасного публичного endpoint snapshot.

## Обновление LucX и восстановление

Обновление запускается отдельным systemd template unit
`lucx-post-update@.service`. Worker сохраняет job ID, фазу, heartbeat и marker
на диске, запускает официальный updater, ждёт его завершения и затем вызывает
transactional repair. Поэтому остановка `x-ui` не уничтожает update-процесс.

Marker удаляется только после успешных стадий:

1. официальный updater завершился успешно;
2. LucX снова доступен;
3. внешний ingress восстановлен;
4. backend listeners готовы;
5. подписки, firewall, сертификаты и заглушки прошли health-check.

При ошибке updater repair не имитирует успех: marker и диагностика сохраняются.

## TUI и команды

Главная команда:

```bash
sudo x-tuna
```

В TUI должны отображаться текущие адреса панели и подписки, состояние служб,
сертификатов, sidecar, firewall, TrustTunnel, последний update job и backup.
Меню, варианты ответа и подтверждения используют числа. Для известных этапов
показывается `[====------] 4/9`; для APT, загрузок и внешних updater показываются
текущая фаза, heartbeat и прошедшее время без фиктивного процента.

Основные CLI-режимы:

```text
--audit          только чтение
--plan           план без применения
--apply          применение после подтверждения
--validate       проверка установленного состояния
--repair-check   read-only проверка drift после обновления
--repair-apply   транзакционное восстановление
--rollback       восстановление выбранного backup
--install-tui    установка постоянных команд
--update-lucx    запуск detached update-worker
```

## Сертификаты

Скрипт ищет сертификаты в известных хранилищах `acme.sh`, Certbot и путях
LucX, проверяет SAN, wildcard, срок действия, совпадение публичных ключей,
права и фактический TLS endpoint. Наличие файла на диске не доказывает, что
его использует служба.

Renewal hook должен проверять новый сертификат, конфигурации, перезапускать или
перечитывать только нужные службы и записывать состояние только после успешной
проверки всех соответствующих TLS endpoints.

## Безопасность и публикация

Перед публикацией обязательны:

```bash
python3 tools/scan_secrets.py
python3 tools/check_documentation.py
```

В Git и release запрещены production IP, домены, пароли, токены, UUID, subId,
subscription URI, private keys, сертификаты, базы и реальные журналы.
Используются `example.test`, RFC5737 IP и синтетические credentials.

## Тестовые ворота

```bash
PYTHONPATH=src:tests python3 -m compileall -q src tests tools
PYTHONPATH=src:tests python3 -m unittest discover -s tests
python3 tools/check_documentation.py
python3 tools/scan_secrets.py
python3 tools/build_installer.py
sh -n install.sh
sh -n install-no-github.sh
sh -n dist/lucx-post-configure.sh
```

На Windows тесты симлинков могут быть пропущены из-за отсутствия привилегий;
на Debian они должны выполняться в Linux-среде. Локальный gate не заменяет
отдельный VPS acceptance: там проверяются реальные listeners, backend,
Cloudflare, подписки, TLS, rollback и отсутствие drift.

## История ключевых решений

- LucX устанавливается вручную, чтобы не смешивать установку панели с
  постконфигурацией и не зависеть от её внутреннего updater.
- Inbound и клиенты создаются вручную; конфигуратор только обнаруживает их и
  строит внешнюю обвязку.
- Исходный Naive Caddyfile защищён, потому что LucX может пересоздать его при
  reconcile, обновлении, изменении клиента или сертификата.
- Sidecar отделён от LucX для совместимости подписок и включается добровольно.
- Неизвестные transports блокируются вместо эвристического перехвата браузера.
- Отдельный update-worker нужен из-за остановки `x-ui` официальным updater.
- Сайты создаются только там, где их публикация не крадёт VPN-трафик.

## Правила обновления документа

Документ обновляется вместе с изменениями manifest schema, write-set,
immutable-set, transport adapters, sidecar, TUI, systemd worker, сертификатов,
firewall и release process. После изменения требуется обновить соответствующие
тесты и разделы `ARCHITECTURE.md`, `CONFIGURATION_RU.md`, `SECURITY_MODEL_RU.md`
или `RELEASE_RU.md`.

Нельзя добавлять в этот файл временные логи, реальные данные сервера или
непроверенные выводы. Все внешние материалы сначала проверяются и
обезличиваются.

## Статус документа

- Состояние: основной контекст для дальнейшей разработки.
- Проверка: полный локальный suite и release gates обязательны перед публикацией.
- Ответственный: проект `x-tuna`.
