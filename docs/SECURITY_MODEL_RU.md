# Модель безопасности

## Базовая граница

`x-tuna` управляет внешней интеграционной обвязкой вокруг LucX. Наиболее
чувствительное состояние LucX считается защищённым по умолчанию. Любое
расширение write-set должно иметь отдельный план, тест и rollback.

## Запрещённые утечки

В исходники, reports, stdout, argv и GitHub нельзя помещать:

- пароли и API tokens;
- UUID, `subId` и subscription URI;
- private keys и содержимое сертификатов;
- AWG/Mieru/TrustTunnel credentials;
- production IP, домены и database snapshots;
- полные клиентские конфигурации.

Диагностика использует redaction и короткие отпечатки. Секреты вводятся без
echo и не передаются через аргументы командной строки.

## Транзакция

Порядок обязателен:

```text
audit → plan → backup → staging → validation → commit → health → rollback
```

Синтаксически некорректный или неполный staging не может быть применён.
При ошибке health-check восстанавливаются все управляемые файлы и разрешённые
метаданные базы.

## Неизменяемые объекты

- исходный Naive Caddyfile;
- клиенты и inbound’ы LucX;
- внутренние listener-порты;
- credentials, UUID, subId и ключи;
- пользовательские файлы, не созданные конфигуратором.

Изменение hash, владельца или режима защищённого файла между audit и commit
останавливает операцию.

## Сеть

Firewall создаётся в отдельной nftables table и не очищает существующие правила.
Cloudflare ACL применяется только к подтверждённым panel/subscription маршрутам.
TrustTunnel internal port блокируется по TCP и UDP только при доказанном внешнем
маршруте через 443; loopback-доступ для HAProxy сохраняется.

## Обновления

Официальный updater LucX выполняется в отдельном systemd worker. Остановка
`x-ui.service` не должна уничтожить worker. До обновления создаются backup и
pending marker; marker удаляется только после успешного repair.

APT-установка не может быть полностью отменена файловым rollback и поэтому
показывается пользователю как отдельное необратимое действие.
